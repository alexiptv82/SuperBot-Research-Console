HISTORICAL_PIPELINE_IDENTITY = UNAVAILABLE

historical_pipeline_identity_basis=
    A completed pre-NEW36 forensic audit of the entire repository history,
    all git blobs, all committed provenance manifests, all session audit
    sidecars (session_audit_24h.csv, session_audit_new12.csv,
    session_audit_36h.csv), all checkpoint reports (CHECKPOINT_24H_REPORT.md,
    CHECKPOINT_36H_REPORT.md), all stage manifests (stage1/2/3_manifest.json),
    the database qa_runs table metadata, and the recovered manifest
    (recovered/MANIFEST.md) found:
    a) No Python source, Jupyter notebook, YAML/JSON configuration, or
       analysis script that produced the CP24/CP36 golden outputs exists
       anywhere in the repository history or filesystem.
    b) No pipeline_sha256, generator_sha256, analysis_sha256, or equivalent
       column appears in any session audit sidecar file.
    c) No provenance manifest, checkpoint report, or metadata sidecar
       records a SHA256 or version identifier for the analysis/scoring
       pipeline used to produce the historical golden CSV outputs.
    d) The V1_2_ACCEPTANCE_CRITERIA.txt BASE document Section I defines a
       pipeline_sha check but supplies no frozen expected reference value.
       The test suite uses only synthetic placeholders
       ("PIPE_SHA_STUB", "P", "p") — no real hash has ever been registered.
    e) The RECONSTRUCTION engine (engine.py, first committed 2026-09-20)
       postdates the CP36 golden production and is a methodology
       reconstruction, not the original generator. Its SHA cannot serve
       as the historical pipeline identity.
    This finding does NOT imply source equivalence between the
    reconstruction engine and the original generator.

# SECTION D — REMOVAL OF VACUOUS PIPELINE EQUALITY CHECK
# =====================================================================
pipeline_sha_equality_check_removed = true

rationale=
    With HISTORICAL_PIPELINE_IDENTITY = UNAVAILABLE, any pipeline_sha
    equality check would require supplying a synthetic, placeholder,
    current-engine, reconstructed-engine, or substitute value as the
    expected hash. Such a check would be vacuous: it would test equality
    against an invented reference with no historical grounding, creating
    a false appearance of integrity verification.

prohibition=
    The following are PROHIBITED as pipeline_sha expected values:
    a) Any placeholder string (e.g., "PIPE_SHA_STUB", "P", sentinel values).
    b) SHA256 of backend/recovery/engine.py or any V1.2 reconstruction file.
    c) SHA256 of any V1.1 engine or spec file.
    d) SHA256 of any file created after the CP36 golden production date
       (2026-09-09, the date of the last NEW12 session).
    e) Any value synthesized, inferred, or derived from the golden CSV
       contents.

# F.A — Horizon invariance
horizon_invariance_check=
    For every tuple (session, asset, feature, q) where the historical
    golden schema provides horizon-repeated threshold values:
    all golden threshold values within that tuple must be identical
    across horizons.
    Equality tolerance: abs(threshold_h1 - threshold_h2) <= 1e-12
    for all horizon pairs (h1, h2) within the same (session, asset,
    feature, q).

# F.B — gap composite threshold identity
gap_composite_threshold_identity_check=
    For every applicable gap_* composite feature:
    golden composite threshold must equal the golden fair_gap_reversion
    threshold for the corresponding structural key
    (session, asset, q [, horizon where applicable]).
    Equality tolerance: abs(gap_composite_threshold -
                            fair_gap_reversion_threshold) <= 1e-12
    Applicable gap_* composites: gap_depthBoth, gap_depthL1,
    gap_depth_extOFI, gap_extOFI, gap_leader1000, gap_localOFI,
    gap_localTrade (subject to presence in the golden schema).

# F.C — leader threshold identity
leader_threshold_identity_check=
    Golden leader1000_extOFI threshold must equal the golden
    leader_gap_1000ms threshold for the corresponding structural key
    (session, asset, q [, horizon where applicable]).
    Equality tolerance: abs(leader1000_extOFI_threshold -
                            leader_gap_1000ms_threshold) <= 1e-12

# F.D — Schema identity
schema_identity_check=
    Golden schema feature set must equal the predeclared blind inventory:
    simple features = {bitget_ofi, bitget_trade_flow, depth_imbalance_l1,
                       depth_imbalance_l5, external_ofi, external_trade_flow,
                       fair_accel_100ms, fair_gap_reversion, leader_gap_100ms,
                       leader_gap_200ms, leader_gap_500ms, leader_gap_1000ms}
    composite features = {depthBoth, depthL1_extOFI, gap_depthBoth,
                          gap_depthL1, gap_depth_extOFI, gap_extOFI,
                          gap_leader1000, gap_localOFI, gap_localTrade,
                          leader1000_extOFI}
    quantile set = {0.8, 0.9, 0.95}
    Any deviation from the predeclared blind inventory triggers
    HISTORICAL_PIPELINE_HETEROGENEITY_DETECTED = true.
