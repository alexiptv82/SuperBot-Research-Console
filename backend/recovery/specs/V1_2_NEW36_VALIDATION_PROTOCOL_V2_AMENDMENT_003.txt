C1. mean_abs_move — INHERITED V1.1 METRIC SEMANTICS

================================================================

classification=
CLARIFICATION_OF_INHERITED_FROZEN_V1_1_METRIC_SEMANTICS

For every HG, HC and HB emitted row for which mean_abs_move is
defined as COMPUTED by Amendment 001:

mean_abs_move_domain=
quality_admissible AND isfinite(forward_return)

mean_abs_move=
arithmetic mean of abs(forward_return) over
mean_abs_move_domain

The domain is evaluated independently for each session, asset and
horizon.

mean_abs_move is FEATURE-INDEPENDENT within the same
(session, asset, horizon).

It does NOT depend on:

threshold crossing
pre-overlap membership
accepted-event membership
variant
feature family
event direction

Therefore, where the same session, asset and horizon apply,
HG/G0, HG/G1, HC/C0, HC/C1 and all HB/B0/B1 rows share the same
mean_abs_move value.

If mean_abs_move_domain contains zero rows:

mean_abs_move=NULL

IMPORTANT:

The parent V2 generic rule
"metric_when_accepted_n_zero=NULL"
does NOT override this inherited feature-independent V1.1
mean_abs_move definition.

mean_signed_bps and hit_rate remain accepted-event metrics.
mean_abs_move is not an accepted-event metric.

This clause is a clarification of inherited frozen V1.1 semantics,
not a NEW36-informed rule and not a new candidate variant.

C2. gate_zero_n — PROSPECTIVE SPECIFICATION COMPLETION

================================================================

classification=
PROSPECTIVE_SPECIFICATION_COMPLETION_BEFORE_NEW36

gate_zero_n is COMPUTED only for HG/G1 rows, as already required by
Amendment 001.

For HG/G1:

di_l1=bitget_depth_imbalance_l1

gate_finite_domain=
quality_admissible AND isfinite(di_l1)

gate_zero_n=
count(
quality_admissible
AND isfinite(di_l1)
AND di_l1==0.0
)

Equivalent:

gate_zero_n=
count of exact-zero di_l1 observations inside the finite
quality-admissible G1 gate population before TZ zero exclusion,
threshold crossing, external-OFI confirmation, forward-return
filtering, or overlap filtering.

Positive zero and negative zero are both equal to 0.0 and therefore
count as zero.

NaN and +/-infinity do not count.

gate_zero_n MUST NOT be computed from:

TZ_threshold_domain after zero exclusion
threshold-crossing events
pre-overlap events
accepted events
external_ofi confirmation

gate_zero_n is invariant across q and horizon for the same
session and asset.

This field is diagnostic metadata only.

It does NOT modify:

TZ threshold
G1 event mask
G1 direction
pre-overlap set
accepted set
event metrics
candidate selection

This exact definition is frozen prospectively before NEW36 access.

It MUST NOT later be represented as historically recovered behavior.
