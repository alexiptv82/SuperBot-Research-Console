3.1 General rule and float comparison rule.

The Candidate application remains a composition/orchestration layer for all
canonical CSV fields.

A009 authorizes only the evidence-only operations in Sections 3.2-3.9 and the generation-time consistency computations of Section 5, including evidence_hit_rate of §5.5.

CANONICAL_FIELDS_CAN_BIND_EVIDENCE=YES

Every A009-introduced comparison of nullable float values, including helper
threshold versus canonical calculated_threshold and evidence-derived hit-rate
versus canonical hit_rate, uses the A008 §10.5 float rule:
  - both NULL => equal;
  - exactly one NULL => mismatch;
  - otherwise both values MUST be finite and abs(a-b) <= 1e-12;
  - NaN or infinity => mismatch/STRUCTURAL failure in the generation-time
    binding context.
No adaptive/relative tolerance and no rounding are permitted.

3.6 Sole direct evidence-only G0 domain-count codification.

The Candidate application MUST NOT read, reference or encode the forbidden
z confirmation-column names for this count. A09 and A12 remain unchanged.

A009 authorizes exactly one direct quantitative count extraction not already
available from canonical HZ counts:

  G0_DERIVED_DOMAIN_N =
  count(
      ctx.quality
      AND isfinite(ctx.columns["bitget_depth_imbalance_l1"])
      AND isfinite(ctx.columns["external_ofi_consensus_l1"])
  )

This is an EXPLICIT_CODIFICATION_OF_EXISTING_FROZEN_SEMANTICS.

Proof basis: the frozen engine._rank_signed_uniform assigns a finite
per-component normalized value exactly to quality-admissible rows whose RAW
component is finite, and NaN otherwise. Therefore the intersection of the two
RAW finite-component domains above is exactly the frozen G0 derived domain
used internally by Stage3.

The Candidate application implementation of this count MUST use only the RAW
column names above and MUST contain no read/reference to the forbidden z
confirmation columns. Static A09/A12 predicates remain fully active and are
not narrowed or weakened.

G0_DERIVED_DOMAIN_N is evidence-only. It MAY be used only:
  (a) as threshold_domain_n under Sections 3.7 and 4;
  (b) by A008 §11.4 / S2 consistency evaluation; and
  (c) by the generation-time fail-closed consistency checks in Section 5,
      including §5.4.

It MUST NOT compute, select or replace a canonical threshold/event/metric.
No other direct threshold-domain count formula is authorized by A009.
